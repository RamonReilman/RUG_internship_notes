### Dataset layout
The folders within GutMock show that there are 2 variants of this set:
- HAC
- SUP
This reveals that 2 out of 3 model generations was used to basecall the raw data. `HAC` stands for high accuracy, whereas `SUP` stands for super-accurate. It is recommended to use `HAC` for most situations, and is the thing i will use for now. I plan to use the `SUP` dataset too, as it is recommended for Savont. But since it is currently unknown to me how it is performed in house, i will use the recommended one.
 
There are four replicates within that `HAC` folder, all containing a singular bam-file. (Introduction - Dorado Documentation, n.d.)

### Data prep
Savant needs fastq as an input, so i will need to make the bam-files into fastq-files. This can be done with bedtools.
```bash
conda install -c bioconda bedtools
```

```bash
dir=/home/hackllab/for-ramon/GutMock/
mkdir "$dir"

for file in /home/hackllab/for-ramon/zymo_16s_2025.09/GutMock/MAB114/hac/*; do
	file_name=$(basename "$file")
	bedtools bamtofastq -i "$file"/*.bam -fq /dev/stdout > "$dir"/"$file_name".fastq
done
```

This gives us 4 replicate fastq files. The bam-files that these fastq's got extracted from holds the `--no-trim` value, meaning that the data wasn't trimmed and still, probably, holds the 16s primers, and barcodes.
