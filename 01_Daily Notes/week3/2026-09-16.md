### GutMock sup
The previous times we ran the tools on data was on the high accuracy gutmock dataset. Today I will also prepare and run the tools on the Super accuracy version. First I will turn the bam files into fastq files, and will give them their own directory.
```bash
dir=/home/hackllab/for-ramon/GutMock_sup/
mkdir -p "$dir"

for file in /home/hackllab/for-ramon/zymo_16s_2025.09/GutMock/MAB114/sup/*; do
	file_name=$(basename "$file")
	bedtools bamtofastq -i "$file"/*.bam -fq /dev/stdout > "$dir"/"$file_name".fastq
done
```
The next thing I will have to do is cut the adapters off the data.

```bash
outpt=/home/hackllab/for-ramon/gutmock_out_sup/trimmed
mkdir -p "$outpt"
for file in /home/hackllab/for-ramon/GutMock_sup/*; do
	file_name=$(basename "$file")
	cutadapt -g 'AGRGTTYGATYMTGGCTCAG' -a 'SGGYTACCTTGTTACGACTT' -O 15 -e 0.1 --report=full -o "$outpt"/"$file_name" "$file"
done
```

#### WF-16s
The first thing I will run on this new data is the WF-16S workflow. This is because this will take alot longer compared to Savont.
```bash
for rep in rep1 rep2 rep3 rep4; do
	nextflow run epi2me-labs/wf-16s \
	--fastq "/home/hackllab/for-ramon/gutmock_out_sup/trimmed/${rep}.fastq" \
	--out_dir /home/ramon/output/runs_out/gutmock_nf_sup/${rep}/ \
	--sample "$rep" \
	--classifier minimap2 \
	-with-apptainer \
	-without-docker \
	--database_set SILVA_138_1 \
	--threads 4 
done
```

#### Savont

savont asv --pooled-samples \

This command has generated the amplicon sequence variants for the SUP data. I can use that as an input to generate a taxonomic profile.

> **Important**: It says here that it was mapped onto silva 138.2, but this is not true. The tool does not support custom databases, but I wanted to align it to the same exact reference as the NextFlow. So I had to rename the folder, but the contents inside belong to version 138.1

### Potato
This is data sequenced and gathered by Thomas Vogel. It has 5 different barcodes. It will be used as an input for the wf-16s and Savont tools. To compare these again later. Savont showed that most of the files were completely empties with a lower max length, so I will set the max length for both tools to 4000, where this warning disappears.

#### Wf-16s
```bash
nextflow run epi2me-labs/wf-16s \
	--fastq /home/hackllab/for-ramon/potato-fungi-18S-20260817/fastq_pass/ \
	--out_dir /home/ramon/output/runs_out/potato/next \
	--classifier minimap2 \
	-with-apptainer \
	-without-docker \
	-process.maxForks 1 \
    -queue-size 1 \
	--database_set SILVA_138_1 \
	--max_len 4000 \
	--threads 2
```

## Notes & Blockers
### End of day thoughts
Today went a lot slower than I had expected, lots of times the nextflow started crashing half way (or even very close to the end of a 2 hour run). With errors that I did not highlight due to the fact that they are unreadable and extremely unclear. Eventually I figured out that the /tmp folder was just full... So after cleaning that up (multiple times after running nextflow) it seemed to now work. This exact issue also came up during the potato data. Eventually I found a nextflow parameter [`maxForks`](https://docs.seqera.io/nextflow/reference/process/directives/max-forks). That gives a way to limit concurrent tasks, making the load for the writing of data less. This caused the process overall to be way slower, but at least it works now.
